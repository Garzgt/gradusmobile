GRADUS SYSTEM MASTER DESCRIPTION (PLAIN TEXT AI CONTEXT)
SYSTEM NAME:
GRADUS – Grade Management, Intelligent Scheduling, Academic Progress Tracking, and Automated Academic Recognition System

INSTITUTION:
Pampanga State University – Sto. Tomas Campus

SYSTEM TYPE:
Academic Management System (Web + Desktop + Mobile Integration)

PRIMARY PURPOSE:
GRADUS is designed to centralize and automate academic scheduling, enrollment, grade encoding, advising plan generation, and recognition qualification for Pampanga State University Sto. Tomas Campus.

The system operates using rule-based logic and deterministic validation. It does NOT use machine learning.

3. WEBVIEW EVALUATION SCAN (ADVISING FEATURE ONLY)
Purpose:
To scan the PSU portal evaluation page via the mobile app WebView when a student opens
the advising feature in their dashboard.

The WebView scan happens inside the advising feature only. It is not used during registration
or as a gate before entering the dashboard.

PSU evaluation page color semantics (student reads these during scan):
- Blue rows: credited/passed subjects — satisfies prerequisites.
- Black rows: failed or dropped subjects — does not satisfy prerequisites.
- Yellow rows: INC (Incomplete) — satisfies prerequisites.
- White/default rows: not credited — does not satisfy prerequisites.

How it works (inside the advising feature):
1. Student opens the advising feature from the dashboard.
2. App opens the PSU portal evaluation page inside a WebView.
3. Student logs in and scans their evaluation results.
4. System reads which subjects are failed, incomplete, or not yet taken.
5. System suggests subjects based on the scan result.
6. Student selects subjects and proceeds to generate the advising form.

============================================================
4. ADVISING FEATURE
Purpose:
To help students who know they are irregular plan their subject enrollment for the current term.
The feature is available to all students in the dashboard but recommended for irregular students only.
The system does not classify or label students — the student decides themselves if they need it.

How it works:
1. Student opens the advising feature from the dashboard.
2. App opens the PSU portal evaluation page via WebView. Student scans their results.
3. System suggests subjects in priority order:
   - Priority A: back subjects (failed/retakes) — listed first.
   - Priority B: current year-level subjects — only if prerequisites are satisfied.
   - No advance subjects from future year levels are allowed.
4. Student selects subjects from the suggested list.
5. System checks the currently published schedule for time conflicts across all selected subjects.
6. If no conflicts — student generates a printable advising form.
7. Student prints the form and submits it as a hard copy to the program coordinator.
8. Student also submits a Letter of Intent (LOI) via the Google Drive link provided by the institution.
9. Program coordinator forwards the advising form together with the LOI to main campus for official enrollment processing.
10. After main campus processes the enrollment, teacher imports the classlist via Excel.

Note: GRADUS does not automate equivalency evaluation for students from other institutions.

5. SCHEDULING ENGINE
Type:
Rule-based deterministic scheduling engine.

Schedule time rules:

7:00 AM – 5:30 PM
30-minute intervals
Monday–Saturday
Constraints:

No teacher overlap
No room overlap
No section overlap
Venue type must match subject type
Year 1 Saturday blocked
NSTP not included in schedule grid
PE venue priority (PE Area → Conference Hall fallback)
Venue program restrictions enforced
Schedules generated as:

Draft
Reviewed
Published
Only PUBLISHED schedules can be used for enrollment.

============================================================
6. ENROLLMENT FLOW
GRADUS has no role in enrollment. The LOI system and main campus handle the entire process.
GRADUS involvement begins only after the teacher imports the classlist.

All students:
1. Submit their Letter of Intent (LOI) through a Google Drive link provided by the institution outside GRADUS.
2. Main campus processes the LOI and creates the official classlist.
3. Teacher downloads the official classlist from the PSU portal.
4. Teacher imports the classlist via subject-level Excel file into the GRADUS Desktop app. Each file covers one section and one subject.
5. After import, teacher begins encoding grades in GRADUS.

Students who use the advising feature also:
- Submit the printed advising form as a hard copy to the program coordinator before submitting the LOI.
- The coordinator forwards the advising form together with the LOI to main campus for official enrollment processing.

Note: The program coordinator is a real-world intermediary in the physical submission process and has no GRADUS system account.

9. GWA COMPUTATION
Formula:
GWA = Σ(Grade × Units) / Σ(Units)

Only enrolled subjects included.
Computed after posted final grade submission.

============================================================
10. ACADEMIC RECOGNITION AUTOMATION
Eligibility Conditions (all four must be met):

1. No back subjects — all enrolled subjects must belong to the student’s current year level
   and current semester only. Any subject from a previous year level or semester disqualifies
   the student immediately.
2. Full standard curriculum load — enrolled units must match the exact curriculum load defined
   for the student’s current year level and semester.
3. All subjects passed — no FAILED, DROPPED, or INC remarks in any enrolled subject for the term.
4. GWA threshold:
   President’s List: 1.00 – 1.25
   Dean’s List: 1.26 – 1.75
   GWA = Σ(equivalent_grade × credit_units) / Σ(credit_units)

If all conditions are met:

Record inserted in academic_honors table
Digital certificate generated
Email notification sent
Published in recognition page
No manual application required.

If any condition fails — student is not qualified for that term.
