# Landing Page Rules And Guardrails

This file defines mandatory rules for content, interaction, and governance on the public landing page.

## 1. Content Rules

1. Every section must answer one user question only.
2. Keep claims specific and verifiable.
3. Avoid internal jargon for public visitors.
4. Keep CTA labels action-first and platform-specific.

## 2. Interaction Rules

1. All primary actions must be visible in hero and final CTA.
2. Navigation links must map to real section anchors.
3. FAQ must be keyboard and screen-reader friendly.
4. Mobile interactions must not depend on hover.

## 3. Public Data Rules

1. Only approved and published academic outcomes can be public.
2. Never expose draft grades or sensitive identifiers.
3. Public achievers ranking must include policy disclaimer.
4. Publish and unpublish actions must be auditable.

## 4. Design Rules

1. Follow PSU-inspired tokens from Color-Scheme.md.
2. Keep consistent spacing and heading hierarchy.
3. Preserve visual contrast for all states.
4. Use motion to support meaning, not decoration.

## 5. Performance Rules

1. Optimize media before deployment.
2. Lazy-load non-critical sections and assets.
3. Keep interaction feedback under short response times.
4. Prioritize mobile-first performance.

## 6. Accessibility Rules

1. Keyboard navigation is required for all interactive elements.
2. Focus indicators must be visible.
3. Semantic headings must be correct.
4. Reduced-motion support must be active.

## 7. Governance Rules

1. Public copy changes should go through review.
2. Ranking criteria changes require policy owner approval.
3. Release checklist must be passed before publish.
4. Keep versioned notes for significant landing-page updates.

## 8. Image and Media Rules

1. Use optimized image formats and size variants for mobile, tablet, and desktop.
2. Keep first-view media budget controlled and lazy-load deeper sections.
3. Use real product or institutional visuals over generic stock imagery when possible.
4. Keep image style cohesive across screenshots, photos, and illustrations.

## 9. Developer Team Profile Rules

1. Only approved team members with consent may appear in public team section.
2. Team cards must include accurate full name and role.
3. Formal portrait standards must be consistent for crop, attire, and quality.
4. Remove or update profiles promptly when membership changes.

## 10. AI-Generated Visual Rules

1. AI-generated cartoon illustrations are allowed only as supportive explanatory visuals.
2. AI-generated visuals must not represent real team members, achievers, or testimonial identities.
3. Use real photos for Developer Team cards and any real-person public profile section.
4. Use real screenshots for product proof where accuracy matters.
5. Keep a consistent style direction for all AI illustrations used on one page.
6. Add a clear disclosure note when AI-generated visuals are included.
7. Use only assets with usage rights suitable for public and commercial deployment.
