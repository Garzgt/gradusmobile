# GRADUS Landing Page Section Blueprint

This blueprint defines required content blocks and behavior per landing page section.

## 1. Header

Required:
1. Logo and wordmark
2. Anchor links: Features, Roles, Team, Achievers, FAQ, Contact
3. Actions: Open Web, Desktop App, Mobile App

Behavior:
1. Transparent over hero at top
2. Solid background after scroll threshold
3. Mobile drawer with clear close state

## 2. Hero

Required:
1. Strong value proposition
2. Supporting sentence with core modules
3. Three primary action buttons
4. Product visual area

Behavior:
1. Staggered reveal order: title, subtitle, CTAs, visual
2. Keep CTA visible above the fold on mobile

## 3. Platform Access Hub

Required cards:
1. Web platform card
2. Desktop platform card
3. Mobile platform card

Per-card items:
1. Availability status
2. Short capability note
3. Main action button
4. Secondary metadata

## 4. How GRADUS Works Timeline

Steps:
1. Schedule generation and publication
2. Enrollment flow by standing
3. Teacher grade posting workflow
4. Recognition outcome publishing

Behavior:
1. Horizontal timeline on desktop
2. Vertical timeline on mobile
3. Progress indicator animation on reveal

## 5. Core Modules Showcase

Tabs or segmented control:
1. Scheduling Engine
2. Enrollment Workflow
3. Grade Management
4. Academic Recognition

Per module panel:
1. One-line summary
2. Three to five capability bullets
3. Supporting media or icon set

## 6. Role-Based Experience

Role switcher options:
1. Super Admin
2. Program Coordinator Admin
3. Teacher
4. Student

Per role panel:
1. What this role can do
2. What this role cannot do
3. Typical daily flow

## 7. Public Academic Achievers

Required:
1. Top achievers list or card grid
2. Term selector
3. Program selector
4. Last updated information
5. Criteria link

Policy guardrails:
1. Show only finalized and published outcomes
2. Respect privacy rules for public display

## 8. Trust and Governance

Required highlights:
1. Deterministic policy engine
2. Audit-ready workflow
3. Posted-only grade visibility
4. Institutional control and accountability

Presentation:
1. Icon plus short statement cards
2. Maximum two lines per statement for scan speed

## 9. Testimonials or Outcome Stats

Option A:
1. Role-labeled testimonial cards

Option B:
1. Pilot outcome metrics if testimonials are unavailable

## 10. Developer Team Showcase

Required:
1. Section title and short intro
2. Team group tabs or filters (Core, Frontend, Backend, Mobile, QA)
3. Formal-photo member cards
4. Optional profile links (portfolio, GitHub, LinkedIn)
5. Team contribution summary row

Per member card:
1. Formal portrait photo
2. Full name
3. Role title
4. Specialization tag
5. One-line contribution

Behavior:
1. Desktop uses card grid with hover detail reveal.
2. Mobile uses clean stacked cards with tap-to-expand details.
3. Card animation stays short and non-distracting.

## 11. FAQ

Required topics:
1. Platform access by role
2. App download locations
3. Grade visibility policy
4. Support process

Behavior:
1. Accordion with smooth open and close
2. One expanded item at a time on mobile

## 12. Final CTA Band

Required:
1. One-line value reminder
2. Three action buttons
3. Contrast-heavy background block

## 13. Footer

Required:
1. Domain identity
2. Quick links
3. Contact and support
4. Copyright and policy links

## 14. Responsive Notes

Mobile first:
1. Single-column stacks
2. Sticky quick-action row
3. Keep text concise for small screens

Desktop:
1. Wider hero and richer visual layout
2. More expressive spacing and composition
